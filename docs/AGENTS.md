# 文档标准

本文件是本项目文档的统一入口。各类文档的属主、位置与适用范围以下面的归属配置为准；其他位置只链接到事实的属主，不复制正文。

## 文档分层

| 文档 | 负责什么 | 不重复承载什么 |
| --- | --- | --- |
| README / 项目指南 | 项目入口、常用操作与进一步阅读路径 | 已由合同或设计文档拥有的完整结论 |
| 工作项 | 本次交付范围、产品行为与验收、评审与批准事实 | 长期技术决定正文 |
| Agent Note | 长期技术提案、已交付决定、真实备选与后果 | 产品合同、工作状态、已有权威设计全文 |
| 领域术语表 | 术语、边界、模块职责与关系 | 临时工作状态与实施步骤 |
| AGENTS.md / 技能 | Agent 行为规则、工作方法与仓库护栏 | 产品及运行时合同 |

上表只用于识别内容归属，不是齐备的模板；不存在的文档类型不为了填表而新建。研究、验证清单、平台事实等专门资料按需建立，不构成默认文档层。

## 项目归属配置

| 内容或类型 | 启用方式与适用范围 | 属主、位置与规则入口 |
| --- | --- | --- |
| 工作项 | 已启用；本次交付范围、产品行为与验收 | 当前任务/对话；本项目未配置 Issue 跟踪器 |
| 工作状态、评审与批准证据 | 已启用；工作项推进 | 当前任务/对话 |
| 产品范围与非目标 | 已启用；项目级边界 | [`scope.md`](scope.md) |
| 机制映射与偏差 | 已启用；参考机制 → DSH 落点对照 | [`dsh-mapping.md`](dsh-mapping.md) |
| 能力账本 | 已启用；全量能力与证据驱动的状态 | 根目录 `capabilities.yaml`；状态只由 `npm run check-capabilities -- --write` 生成 |
| Agent Note | 已启用；长期技术提案、设计、决定、备选与理由 | 记录根 `.agents/notes/`（`proposed/`、`implemented/`、`rejected/`、`archived/`）；格式与生命周期遵循 `write-agent-notes` Skill；工作项链接到 Note |
| 领域术语表 | 已启用；单上下文 | 根目录 `GLOSSARY.md`；术语需要收敛时由 `domain-modeling` Skill 建立，当前不存在 |
| 独立 RFC／ADR | 新工作未启用 | 相应技术设计与决定归 Agent Note |
| 独立 Spec | 按需启用；跨工作项持续生效的行为合同 | 首次需要时先登记属主、适用范围、位置与规则，再创建正文 |

已启用的类型即使还没有记录，也按上表登记位置或创建规则；记录目录在首份记录需要时创建。

## 一个事实一个家

每个事实由负责它的属主完整说明，其他位置只链接。

- 一份文档的读者和用途决定它写多细；别替其他层写细节，在当前位置链接到内容属主。
- 写文档先确定归属和位置，再确定本层的细节程度；不属于本层的内容搬回属主。
- 机器能生成或校验的清单（迁移列表、路由表、测试清单、包与端点目录）不手抄，链接到源码或生成物。
- 文档类型不扩大它的职责：Spec 修订记录只保留修订标识、受影响章节、合同变化摘要和生效情况。

## 写作规则

- **写当前状态**：变更过程归提交与工作项；Agent Note 保存仍有长期价值的决策依据。
- **保留完整命题**：删形容词、重复和叙述前，确认事实仍完整，包括执行者、动作、条件、时序、义务强度与负面影响。
- **一个段落一行**：用编辑器软换行；表格、代码块和列表保持原有格式。
- **事实与推论分开**：可核实的事实标明证据位置（用例名、命令、留档路径）；推论、估计与待确认事项明确标注。
- **用能指向具体对象的词**：写端点、字段、类型、表、命令或行为本身；复用仓库已定义的术语。
- **不写推理过程**：保留结论、合同和未来仍有用的理由；删除实现步骤叙述与被否决的局部备选。
- **不写状态标注**：避免“已实现”“未来会……”等会随交付腐坏的文字；状态由工作项、目录和代码表达。
- **强调节制**：加粗只用于改变行为的句子或真正重要的对比。

## 检查

Agent Note 的目录、格式、正文骨架和本地链接由 `write-agent-notes` Skill 的校验脚本检查；管理根的 `package.json` 提供覆盖已选 Notes 根的 `verify-notes` 命令。机械检查通过不代替对事实归属与合同完整性的审阅。
