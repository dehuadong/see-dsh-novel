# 领域文档消费规则

工程类技能在探查代码库前，按本文说明读取本项目的领域文档。

## 探查前先读这些

用项目指令指向的文档入口 [`docs/AGENTS.md`](../AGENTS.md) 定位本次任务适用的术语表、设计与决定。

- **`GLOSSARY.md`** — 位于仓库管理根（本项目根目录）。本项目为单上下文，不使用 `GLOSSARY-MAP.md`。文件当前不存在；术语需要收敛时由 `domain-modeling` Skill 建立，不要为满足配置而预建空表。
- **已登记的设计与决定来源** — 按 [`docs/AGENTS.md`](../AGENTS.md) 的归属配置读取；长期技术决定归 `.agents/notes/` 下的 Agent Note，格式与生命周期遵循 `write-agent-notes` Skill。

路径从仓库管理根解析，而不是当前子目录；普通 Markdown 链接按所在文件相对解析。必需的输入缺失或其适用范围与其他输入冲突时，报告具体缺口和受影响工作，不要自行假设。

## 使用术语表的词汇

输出中出现领域概念时（议题标题、重构提案、假设、测试名），使用 `GLOSSARY.md` 定义的术语，不要漂移到术语表明确避免的同义词。

概念尚未进入术语表时，先判断是引入了项目未使用的说法（重新考虑），还是确实存在缺口（记录到 `/domain-modeling`）。

## 标记决定冲突

输出与适用决定冲突时，指出配置来源并说明冲突：

> _与关于订单事件的现行 Agent Note 冲突 —— 因为……需要重新审视该决定。_
