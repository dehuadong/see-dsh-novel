## 1. 阶段概述

剧本创作的最终阶段是**从机器内部的数据结构向真实影视拍摄、游戏引擎及商业发行的工程交付转换**。不同于小说只需输出纯文本，剧本必须根据下游不同的工业生产线进行针对性格式编译：
1. **影视拍摄组**：需要标准的 Markdown/PDF 分场剧本与视听分镜表；
2. **AI 生图团队**：需要严格编号对齐的提示词集与资产清单（`assets.json`）；
3. **互动影游开发团队（Unity/Unreal/Godot）**：需要符合游戏叙事标准的 **Inkle Ink 脚本（`.ink`）**；
4. **制作人/投资人/测试团队**：需要无需任何开发环境、双击即可在浏览器中试玩的**单文件交互网页（Standalone HTML）**。

---

## 2. 执行主体与角色编排

- **InteractiveFilmAuthoringStore**：负责剧本图谱的微观修订（增删节点、重连分支、调整台词）。
- **Ink Exporter（export-ink.ts）**：负责将 `StoryGraph` 编译为符合游戏工业标准的 Ink 语言。
- **HTML Exporter（export-html.ts）**：负责将图谱、分镜、变量状态机与对白打包为一个自包含的响应式网页。
- **PipelineRunner**：协调全局产物的最终打包与分发。

---

## 3. 输入契约与上下文来源

- **验证通过的剧本图谱（StoryGraph）**：通过第六阶段交付校验的完整数据模型。
- **分镜资产清单（assets.json）** 与已选定的定稿图片路径。
- **修订编辑请求（Author Edit Scope）**：来自作者的局部微调操作（如替换某句对白或修改分支条件）。

---

## 4. 输出产物与权威形态

1. **工业游戏脚本（script.ink）**：
   - 带有 Knot、Stitch、Divert 与状态条件的完整 Ink 语言文件。
2. **单文件交互网页（preview.html）**：
   - 内置 CSS 样式、JavaScript 状态求值引擎与图片资源的单文件 HTML，支持离线点击试玩。
3. **分镜印刷物与资产包**：
   - `storyboard.md` 结合 `assets/selected/` 下的定稿渲染图。

## 5. 核心流转机制与关键算法

### 5.1 微观图谱局部微调（Authoring Tools）
在修订阶段，编剧无需重新生成整部剧本，可通过专有工具执行精确到节点的操作：
- `connect_choice`：在两节点间新建或重连一条分支选择；
- `remove_node`：安全删除节点，并自动提示断连的上游选项；
- `draft_structure`：调整指定节点的对白、动作描写与生图 Prompt。

### 5.2 Inkle Ink 工业语言编译器（export-ink.ts）
系统遍历 `StoryGraphNode`，按 Ink 规范生成 Knots：
```ink
=== node_cellar_interrogation ===
苏晴站在潮湿的冷库地下室，手电光照在斑驳的墙壁上。
赵大勇步步逼近，眼神阴冷。

* [出示搜出的假账本] -> choice_present_ledger
* {has_key == true} [用备用钥匙反锁铁门] -> choice_lock_door
* [转身逃跑] -> choice_flee

=== choice_present_ledger ===
~ trust_level = trust_level - 10
~ knows_truth = true
-> node_confrontation_climax
```
- 自动将 `Condition` 转换为 Ink 的内联条件语法 `{var == val}`；
- 自动将 `StateEffect` 转换为变量赋值语句 `~ var = val`。

### 5.3 单文件自包含 HTML 生成器（export-html.ts）
为了向非技术背景的制片人与导演汇报，系统将图谱编译为开箱即用的网页：
1. **内嵌运行时**：将 `evaluator.ts` 与状态机逻辑以原生 JavaScript 内嵌在 `<script>` 中；
2. **纯前端状态机驱动**：支持保存进度、回溯上一步（Undo）、查看当前背包（Inventory）与好感度面板；
3. **分镜图画廊**：若资产已生成图片，节点上方自动渲染当前镜头的视觉氛围图。

## 6. 数据结构与代码实现节选

### 6.1 `exportToInk` 实现要点
```typescript
// packages/core/src/interactive-film/export-ink.ts
export function exportStoryGraphToInk(graph: StoryGraph): string {
  const lines: string[] = [
    `// Generated by InkOS Interactive-Film Engine`,
    `// Title: ${graph.title}`,
    "",
    "// Global Variables",
    ...Object.entries(graph.initialState).map(([k, v]) => `VAR ${k} = ${JSON.stringify(v)}`),
    "",
    `-> ${graph.rootNodeId}`,
    "",
  ];
  for (const node of graph.nodes) {
    lines.push(`=== ${node.id} ===`);
    lines.push(node.content); // 场景描写与对白
    for (const choice of node.choices) {
      const cond = choice.condition ? `{${renderInkCondition(choice.condition)}} ` : "";
      lines.push(`+ ${cond}[${choice.label}]`);
      if (choice.effects) {
        for (const eff of choice.effects) lines.push(`    ~ ${eff.var} = ${eff.value}`);
      }
      lines.push(`    -> ${choice.targetNodeId}`);
    }
    lines.push("");
  }
  return lines.join("\n");
}
```

## 7. 质量门禁与强校验规则

1. **Ink 语法编译合法性断言**：
   - 导出的 Ink 脚本必须符合官方语法树规范，所有 Divert（`-> target`）指向的目标 Knot 必须真实存在。
2. **单文件 HTML 零外链要求**：
   - 生成的 HTML 严禁依赖任何外部 CDN 库（如无需外链 Vue/React），确保在绝对断网环境下依然能流畅运行。

---

## 8. 一致性与因果链保障

- **多端交付数据同一律（Artifact Identity）**：
  无论是查看 `script.md`、游玩 `preview.html` 还是将 `script.ink` 导入游戏引擎，其背后的节点内容、分支选项与因果判定完全由 `story-graph.json` 编译而来，保证制作、演出与程序接入 100% 同步。

---

## 9. 创作技能与专业方法论

技能 `inkos-interactive-film` 在交付阶段的指导：
- **可维护性与资产解耦**：场景描写、台词对白与生图提示词必须能够独立热更微调，换一套视觉风格不应该破坏底层剧本的因果分支。
