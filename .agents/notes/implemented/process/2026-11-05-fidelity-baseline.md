# Agent Note: 保真基线 —— 源工程是复刻对象，不是「参考」

Status: implemented

## Problem

前一阶段的记录与口径把 `inkos/` 称作「参考工程」，把本仓库与它并列成「参考 vs 我们」，并据此把一批实为缺失／放宽的差异记成「有意偏差」。这个口径让保真债失去优先级：只要写进笔记，偏差就看起来已经处理；P1 复审因此才发现 `book_rules.json` 缺版本、就绪判据过松、truth 投影与控制文档缺失、伏笔字段被丢弃。术语错位会持续生产同类债。

## Decision

`AGENTS.md` 增加「保真原则」，并把开头定位改成「源工程 → 高保真复刻」：

- `inkos/` 是**源工程**，本仓库是**复刻**；文档不写「参考工程」。
- 行为等价优先于「能跑」；每行能力对应源工程的一个纵向能力。
- 偏差只有两种合法来源：DSH 机制无法等价，或源行为不可观测；两者都要写进 `docs/dsh-mapping.md` 的「偏差登记」（源工程做法 → 复刻做法 → 原因 → 验证）。
- 缺字段、缺文件、放宽校验、合并或拆分流程都算**保真债**，必须当行补齐或记入 `docs/scope.md` 的后续阶段。
- 账本字段 `reference:` 改名 `source:`，值仍是源工程证据位置（`inkos:…` 模块路径）。

`docs/dsh-mapping.md` 的表头改成「源工程做法 / 复刻做法」，并在开头写明偏差的登记前提；`docs/scope.md` 的术语同步，且注明它只描述范围与顺序、保真判据归 `AGENTS.md`。

边界检查脚本同步术语：`isSourceSpecifier`、`SOURCE_SEGMENTS`、问题码 `source-import`；它检查的是「依赖说明符指向源工程」，不是「指向参考」。

## Alternatives considered

**保留「参考工程」叫法，只在笔记里声明保真优先。** 省一次改名。否掉：口径决定默认动作；「参考」允许选择，复刻不允许。术语不改，偏差记录会继续被当成合理选择。

**把历史笔记全部改写。** 口径彻底统一。否掉：历史笔记是当时的决策记录，改写会抹掉演进痕迹；新口径写入 `AGENTS.md` 与本篇，旧篇保持原样。

**只改文档，不改账本字段。** 少一次全表改动。否掉：字段名是每天读的东西，`reference` 会持续暗示对等实现；改名成本是一次机械替换 + 校验脚本一行。

## Consequences

收益：仓库里有一个明确判据——能等价的必须复刻，不能等价的必须登记。偏差不再因为被写下来就自动合理；「保真债」成为可追踪的对象。

落地：`AGENTS.md` 的保真原则与三条定位引用、`docs/scope.md` 的术语与指向、`docs/dsh-mapping.md` 的登记前提与表头、`capabilities.yaml` 47 行的 `source:` 字段、`scripts/check-capabilities.mjs` 的字段名、`packages/see-dsh-novel/src/tools/boundary.ts` 的术语与 `source-import` 问题码（测试同步）。

代价与已知限制：

- 历史笔记与早期真实运行回执保留旧术语（回执是历史证据，不改写）。
- `source:` 只记模块路径，不表达「该模块的哪些行为已复刻」；后者由行内实现与消费者表达。
- 保真债清单由 `docs/scope.md` 承载，未自动生成；新增债务要人工登记。
