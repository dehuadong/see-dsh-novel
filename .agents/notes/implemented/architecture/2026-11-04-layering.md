# Agent Note: 分层是 core / pipelines / client / plugin，构建是单文件打包

Status: implemented

## Problem

P0 时只有一个包、一层目录，`story-next` 与 foundation 混在 `src/` 下。往后要加短篇与剧本。三者共享作品目录、写入语义与状态文件，但各自的阶段、工具与产物不同；如果都摊在一个目录里，两个月后没人说得清哪个文件属于哪条流水线。

同时，`tsc` 多文件输出的形态不适合作为插件产物：DSH 用原生 `import()` 装载，插件目录里没有跨包 `node_modules`，多文件产物一旦引入工作区依赖就会在装载期失败。

## Decision

### 源码分三层

```
src/
  core/                 # 共享：类型、原子写入、状态播种
  pipelines/
    long/               # 长篇：foundation（后续 plan/chapter 同级）
    short/              # 短篇（未建，落地时新建）
    script/             # 剧本（未建，落地时新建）
  client/               # 浏览器半边：视图组件、槽位注册、样式（只依赖宿主客户端包）
  plugin/               # 装配：根入口、agent 入口
```

依赖方向单向：`plugin → pipelines → core`。pipeline 之间不得互相 import，也不能反向依赖 `plugin`；`client` 是独立的浏览器半边，不 import 本仓库的 `core`／`pipelines`／`plugin`，只依赖宿主客户端包与 `react`。这三条都写在 `test/boundaries.test.mjs` 里机械检查，不靠约定。

短篇与剧本落地时各自建 `pipelines/<name>/`，共享的部分先抽到 `core`，不允许从 `long` 里 import。什么时候把某个 pipeline 拆成独立包：当它需要自己的依赖、自己的构建入口，或需要在别的插件里复用时——目前不拆。

### 产物是单文件

`scripts/bundle.mjs` 用 esbuild 打三个入口：`lib/index.js`、`lib/agent.js`（node 平台，`@deepseek-ai/*` 与 `node:*` 外部化），以及 `lib/client.js`——浏览器半边是 CJS 产物，由 `window.__ModuleLoader__.load({ id, factory })` 包起来，`require('react')`／`require('react/jsx-runtime')` 走宿主模块表。每次构建先清空 `lib/`，产物内不允许残留相对导入（`from "./…"` 与 `require("./…")` 都查）。

`tsc` 只做 `--noEmit` 类型检查，不产出文件。测试用 `tsx` 直接跑 `src/*.ts`，与产物解耦。

## Alternatives considered

**继续用 tsc 多文件输出。** 最简单，产物目录结构直观。否掉：DSH 装载器不补扩展名、不提供跨包解析；一旦 pipeline 之间有共享包，多文件产物会在装载期失败，而这个问题只在真机出现。

**把所有代码留在单层 `src/`，用文件名前缀区分。** 零成本。否掉：短篇/剧本各自有阶段与工具，前缀只能表达归属，不能表达依赖方向，也无法机械检查。

**现在就拆成三个 workspace 包（core / long / bundle）。** 边界最硬。否掉：当前只有一个 pipeline，拆包要额外维护三份 package.json、三条构建链与跨包构建顺序；分层目录 + 边界测试已经能挡住横向依赖，拆包的收益等第二个 pipeline 真正落地再兑现。

**client 也走 node 平台的 ESM 产物。** 少一条构建分支。否掉：浏览器模块由 `__ModuleLoader__` 以脚本方式求值，产物要包在 `factory(require)` 里，`require('react')` 由加载器注入、不能被打包器解析——Esm 产物做不到这两点，所以 client 单独走 CJS＋包裹。

## Consequences

收益：新增短篇或剧本时只需要一个 `pipelines/<name>/` 目录加一次 `plugin` 装配，不用碰长篇的代码；构建形态与 DSH 自身插件一致，装载期不会再有扩展名或跨包解析问题。

代价：

- 每次构建都清空 `lib/`，未重新构建时运行中的插件仍是旧产物。
- esbuild 的 external 是白名单式约定：新增宿主提供的包时必须同步加到 `HOST_EXTERNAL`，否则会被内联进产物。
- 分层由 `test/boundaries.test.mjs` 机械检查：pipeline 之间、pipeline → plugin、client → 本仓库其它层；`core` 内部的模块划分仍靠人工判断。
